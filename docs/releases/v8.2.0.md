# Financial AI Copilot V8.2.0

**Release date:** 2026-08-18

**Tag:** `v8.2.0`

**Comparison baseline:** `v8.1.0-production`

V8.2.0 is the first GitHub Release after V7.3.3. It aligns the
source-controlled application version, deployment metadata, release tag, and
GitHub Release while consolidating the production work that previously existed
only on the V8.1 tags and `main`.

## Highlights

- **Persistent agent runtime** — Source-controlled LangGraph
  plan/execute/finalize orchestration with PostgreSQL-backed sessions,
  checkpoints, messages, and trace persistence.
- **Governed tools and MCP** — Tenant-scoped retrieval and deterministic
  financial-metrics tools, default-deny authorization, schema validation, and a
  stdio JSON-RPC MCP server verified with the official TypeScript SDK harness.
- **Tenant-safe RAG** — Semantic and BM25 hybrid retrieval, financial query
  enrichment, explicit public-knowledge policy, remote Chroma lifecycle
  handling, and tenant-isolation tests.
- **Structured document ingestion** — Page- and section-aware PDF parsing, OCR
  fallback with quality gates, provenance metadata, asynchronous indexing,
  SHA-256 duplicate rejection, and idempotent public-demo bootstrap.
- **Multi-provider runtime** — Registered adapters and settings contracts for
  DeepSeek, Gemini, OpenAI, Anthropic, and Doubao; user-scoped provider/model
  selection with encrypted credentials.
- **Authenticated React Copilot** — Login and registration, conversation
  history, knowledge upload and task status, citation-aware reports, provider
  settings, English/Chinese UI, light/dark themes, responsive layout, and typed
  API contracts.
- **Evaluation and training readiness** — Versioned
  planning/retrieval/model datasets, deterministic CI gates, prompt
  version/checksum tracking, and an explicit opt-in Hugging Face/PEFT LoRA path.
- **Production operations** — Canonical six-service Compose stack (`frontend`,
  `backend`, `agent-worker`, `postgres`, `redis`, `chromadb`), Alembic
  migrations, health/readiness checks, monitoring, rate limiting, and
  PostgreSQL/Chroma backup and restore tooling.

## Security and isolation

- Server-owned tenant/user/thread scope across sessions, retrieval, documents,
  and provider settings.
- Production JWT secret validation, explicit CORS configuration, request-rate
  limits, and runtime error redaction.
- Provider credentials are encrypted with dedicated rotatable key material;
  APIs expose only key hints, never the stored secret.
- Outbound HTTP, Python, and SQL tools remain disabled until separately reviewed
  sandboxes/adapters are provided.

## Upgrade notes

1. Back up PostgreSQL and Chroma data before upgrading.
2. Use the repository-root `docker-compose.yml`; files under `deploy/` and the
   Streamlit path are retained only as historical or secondary references.
3. Refresh `.env` from `.env.example` and set non-placeholder
   `AUTH_SECRET_KEY`, `POSTGRES_PASSWORD`, and `REDIS_PASSWORD`. A configured
   provider credential is required for live LLM responses.
4. The backend entrypoint applies `alembic upgrade head` before starting the
   API. Non-Compose deployments must apply the same migrations explicitly.
5. Existing volumes are preserved by ordinary `docker compose down`; do not use
   `down -v` during an upgrade.

successfully:

- **Backend:** 1,656 credential-free tests passed; 90.35% measured coverage
  against the 85% gate.
- **CI partitions:** 242 unit tests and 40 integration tests passed.
- **Evaluation:** 82 contract tests; offline planning 6/6 at score 100;
  deterministic retrieval 5/5 with Recall@K/MRR/nDCG/citation-source 100 and
  zero tenant leaks.
- **MCP:** 2/2 official SDK stdio conformance cases passed, including
  default-deny behavior.
- **Frontend:** 28 contract/scroll tests passed; TypeScript and Vite production
  build succeeded.
- **Containers:** Compose configuration, backend/frontend image builds, and
  backend/worker import smoke checks succeeded.

Final release publication is gated on the V8.2.0 release commit passing the
same CI and production-validation workflows.

Docker Hub publication runs when the repository's `DOCKER_USERNAME` and
`DOCKER_PASSWORD` Actions secrets are configured. Their absence does not bypass
the required Compose image-build validation or block the source release.

## Known limitations

- CI is credential-free: it does not prove live
  DeepSeek/Gemini/OpenAI/Anthropic/Doubao availability or answer quality.
- Offline planning and deterministic retrieval gates are regression signals,
  not an LLM judge, citation-faithfulness proof for generated prose,
  production-latency benchmark, or substitute for human financial review.
- MCP transport is local stdio only; no public Streamable HTTP MCP endpoint is
  exposed.
- No trained LoRA adapter is bundled. Training is dry-run-first, requires
  separate optional dependencies/hardware/operator confirmation, and must pass
  independent quality review.
- Automated CI validates frontend contracts and production builds, but does not
  claim full visual browser E2E coverage.
